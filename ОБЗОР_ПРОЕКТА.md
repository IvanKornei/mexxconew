# Обзор проекта HFT Arbitrage System

Документ описывает устройство и логику кода, объясняет как запустить дашборд и какие функции выполняет система.

---

## 1. Что это за проект

**HFT Arbitrage System** — высокочастотная торговая система для арбитража пары **BTC/USDT** между **Binance Futures** и **MEXC Futures**.

Ключевая идея:
- Binance — ведущая (быстрая) биржа.
- MEXC — отстающая биржа с задержкой 200–500 мс.
- Когда на Binance появляется резкое движение цены, MEXC «догоняет» его с лагом.
- Система ловит этот лаг, открывает позицию на MEXC в направлении движения Binance и закрывает после «подтягивания» цены.

Проект состоит из двух частей:
- **Backend** — на **Rust** (Tokio, Axum), выполняющий всю торговую логику, WebSocket-сервер, работу с биржами и эмуляцию браузера.
- **Frontend** — на **Angular 21** (signals + Tailwind), реализующий дашборд реального времени.

## 2. Архитектура в общих чертах

```
                 ┌────────────────────────┐
   Binance WS ──►│                        │
                 │  PriceFeedManager      │──► PriceState (watch::channel)
   MEXC WS   ──►│                        │           │
                 └────────────────────────┘           │
                                                      ▼
                                      ┌─────────────────────────────┐
                                      │  PositionManager            │
                                      │   + ImpulseStrategy         │
                                      │   + CapitalManager          │
                                      │   + TradingModeManager      │
                                      └─────────────────────────────┘
                                                      │
                                   ┌──────────────────┴──────────────────┐
                                   ▼                                     ▼
                         Emulation (SQLite)                   Live (BrowserActions + Binance)
                                   │                                     │
                                   └──────────────┬──────────────────────┘
                                                  ▼
                                         WsServer (Axum)
                                                  │
                                          ws://:3001/ws
                                                  ▼
                                   Angular Dashboard (localhost:4200)
```

Поток данных:
1. Два WebSocket-коннектора получают цены с Binance и MEXC в реальном времени.
2. `PriceState` атомарно обновляется и рассылается через `tokio::sync::watch`.
3. `PositionManager` на каждое обновление прогоняет стратегию `ImpulseStrategy`, проверяет сигналы входа/выхода и управляет позициями.
4. Все сделки пишутся в SQLite (отдельные БД для режимов Emulation и Live).
5. `WsServer` рассылает состояние по WebSocket на фронтенд и принимает команды от клиента (старт/стоп, смена режима, обновление настроек).
6. Angular-дашборд подписан на WebSocket и отображает цены, спреды, лаги, позиции и статистику.

## 3. Структура backend (Rust)

Главный модуль — `src/main.rs`. Подмодули:

### `src/core/` — основная логика
- **`state.rs`** — `PriceState`: текущие цены Binance/MEXC, спред, лаги, временные метки, индикатор возможности скальпинга.
- **`price_feed.rs`** — `PriceFeedManager`: запускает по одной задаче на биржу + отдельную задачу под стратегию + stale-checker + сборщик метрик каждые 30 секунд.
- **`spread.rs`** — расчёт сырого и «чистого» (с учётом комиссий) спреда.
- **`trading_strategy.rs`** — `ImpulseStrategy`: сигнал входа как взвешенная сумма трёх компонентов:
  - `momentum_weight` — импульс цены на Binance,
  - `lag_weight` — статистика отставания MEXC,
  - `price_diff_weight` — текущая разница цен.
  Порог входа `total_signal > 0.5`; направление выбирается по знаку импульса и разницы цен. Закрытие по тейк-профиту, стоп-лоссу или таймауту `quick_exit_timeout_ms`.
- **`position_manager.rs`** — `PositionManager`: главный оркестратор позиций. Проверяет включена ли торговля, обрабатывает `PriceState`, открывает/закрывает позиции с защитой от гонок через `AtomicUsize`, пишет сделки в БД, обновляет капитал и собирает метрики задержки обработки.
- **`capital_manager.rs`** — управляет балансом, размером позиции, плечом, комиссиями taker (0% до объёма $1M, 0.01% после).
- **`system_manager_optimized.rs`** — `SystemManager`: состояние системы (running/mode/settings), сохранение/загрузка из файла, переключение режимов, debounced save.
- **`trading_mode_manager.rs`** — `TradingModeManager`: два независимых SQLite-файла (`.kiro/emulation.db` и `.kiro/live.db`), чтобы эмуляционные и реальные сделки не смешивались.
- **`circuit_breaker.rs`** — защита от reconnect-шторма при падении бирж.
- **`time_sync.rs`**, **`price_synchronizer.rs`**, **`price_matcher.rs`**, **`arbitrage_decision.rs`** — расчёт реального лага MEXC и принятие решений.
- **`ring_buffer.rs`**, **`trading_history.rs`** — буфер истории цен и хранилище сделок.

### `src/exchanges/` — коннекторы бирж
- **`binance.rs`** — WebSocket-коннектор к `fstream.binance.com/ws/btcusdt@aggTrade`, парсинг через `simd-json`, circuit breaker, экспоненциальный бэк-офф, heartbeat для health checker.
- **`mexc.rs`** — WebSocket к `contract.mexc.com/edge`.
- **`binance_client.rs`**, **`mexc_client.rs`**, **`mexc_rest.rs`** — REST-клиенты для отправки ордеров (Live).
- **`mexc_emulator.rs`** — симулятор исполнения в режиме эмуляции.

### `src/emulation/` — эмуляция браузера для MEXC
Поскольку у MEXC нет публичного API для фьючерсов, торговля Live идёт через автоматизацию настоящего Chrome через CDP (Chrome DevTools Protocol):
- **`browser/`** — управление Chrome, «человеческий» ввод, fingerprint, `BrowserActions` (заглушка в репозитории).
- **`browser_cookies.rs`** — извлечение cookies из установленного Chrome/Edge/Firefox (AES-расшифровка на Windows).
- **`mexc_cookie_client.rs`** — REST-клиент, использующий извлечённые cookies для авторизации.
- **`session/`**, **`persistence/`** — шифрованное хранилище сессий (AES-256-GCM, ключ из `EMULATION_SESSION_KEY`).
- **`behavior/`** — человеческие задержки (`human_jitter`), периодическая активность, скроллы.
- **`tls/`**, **`proxy.rs`**, **`recovery.rs`**, **`mode_manager.rs`** — TLS-фингерпринт, поддержка прокси, автовосстановление, режимы `Hybrid`/`Aggressive`.

### `src/trading/` — альтернативная схема движка
- **`strategy.rs`**, **`engine.rs`**, **`executor.rs`** — более верхнеуровневый `TradingEngine` с режимами `DryRun` / `Paper` / `Live`. В `main.rs` используется именно `PositionManager`, но API `trading_control` ссылается на эту схему.

### `src/api/` — HTTP/WebSocket API (Axum)
- **`websocket.rs`** — главный эндпоинт. Отдаёт `WsMessage` (цены + позиции + статистика) и принимает команды:
  - `updateSettings` — обновить веса стратегии;
  - `updateCapital` — изменить капитал/плечо/число позиций;
  - `startTrading` / `stopTrading` — включить/выключить торговлю;
  - `switchMode` — переключить между `Emulation` и `Live`;
  - `getSettings` / `getSystemState` — получить текущее состояние.
  Встроенная валидация: веса в `[0,1]` и сумма ≈ 1, плечо 1–200, капитал ≤ $1M, защита от сообщений > 10 КБ.
- **`trading_control.rs`** — REST-эндпоинты `/api/trading/*` (status, start, stop, config, stats).
- **`browser_control.rs`** — REST для управления Chrome (`/api/browser/start`, `/trade`, `/balance`, `/positions`).
- **`cookie_management.rs`** — REST для работы с cookies MEXC.
- **`emulation_status.rs`** — `/api/emulation/status`.

### `src/utils/`
- **`config.rs`** — загрузка `config.toml`.
- **`health.rs`** — `HealthChecker` и `SystemHealth` с эндпоинтами `/health` и `/health/detailed`.
- **`metrics.rs`** — `LatencyMetrics`: гистограмма задержек по бакетам `<10μs`, `10–50μs`, `50–100μs`, `>100μs`.
- **`logging.rs`**, **`rate_limiter.rs`**, **`errors.rs`** — служебные модули.

## 4. Что делает `main.rs` при запуске

1. Подключает HFT-аллокатор `mimalloc` (на 30–50% меньше джиттера).
2. Инициализирует `rustls` и `tracing`-логирование.
3. Грузит `.env` и `config.toml`.
4. Создаёт `SystemHealth` + health-checkers для Binance и MEXC.
5. Строит `PriceFeedManager`, который одновременно создаёт `PositionManager` с параметрами капитала из конфига.
6. Создаёт `TradingModeManager` (две SQLite-базы) и связывает его с `PositionManager`.
7. Включает торговлю в режиме эмуляции по умолчанию.
8. Создаёт `SystemManager` и загружает сохранённое состояние (бывший режим, настройки). В Live режиме выводит предупреждение.
9. Поднимает `WsServer` с маршрутами `/ws`, `/health`, `/health/detailed`, `/api/emulation/status`.
10. Параллельно стартует price-feed и WebSocket-сервер через `tokio::spawn`.
11. Ждёт `Ctrl+C` и делает graceful-shutdown с паузой 2 секунды.

## 5. Структура frontend (Angular 21)

Папка `frontend/src/app/`:

- **`app.component.ts`** — корневой компонент. Собирает весь дашборд: control panel, статус эмуляции, карточки цен, визуализатор спреда, статистика, анализ лага, настройки, таблица истории.
- **`services/market-data.service.ts`** — главный сервис. Открывает WebSocket на `ws://localhost:3001/ws`, автоматически реконнектится через 2 секунды, парсит входящие сообщения в сигналы Angular (`data`, `historyData`, `positionsData`, `tradingStatsData`, `recentTradesData`, `systemState$`). Экспортирует команды: `startTrading`, `stopTrading`, `switchMode`, `applyStrategySettings`, `applyCapitalSettings`.
- **`services/cookie-management.service.ts`** — работа с cookies MEXC через REST.
- **`services/emulation-data.service.ts`** — данные эмуляции.
- **`components/control-panel.component.ts`** — кнопки «Запустить/Остановить», переключатель режима с подтверждением перехода в Live.
- **`components/price-card.component.ts`** — карточка цены биржи.
- **`components/spread-visualizer.component.ts`** — визуализация спреда.
- **`components/positions-panel.component.ts`** — панель открытых позиций.
- **`components/history-table.component.ts`** — таблица истории сделок.
- **`components/trading-settings.component.ts`** — настройки стратегии (веса, пороги, таймауты, капитал, плечо).
- **`components/trading-stats.component.ts`** — статистика из БД (total_trades, win_rate, PnL).
- **`components/trading-config-page.component.ts`** — страница конфигурации.
- **`components/notification.component.ts`** — уведомления.
- **`components/emulation-status/`** — статус браузерной эмуляции.
- **`components/browser-control/`** — управление Chrome.
- **`components/settings-page/`** — страница настроек.

Стили — Tailwind CSS, тема в духе Bloomberg, используется реактивная модель Angular Signals.

## 6. Как запустить дашборд (локально)

### Требования
- Rust 1.84+
- Node.js 20+ и npm
- Chrome/Edge/Firefox (для Live режима MEXC)

### Шаги

1. Подготовка переменных окружения:
   ```bash
   cp .env.example .env
   # Сгенерируйте 64 hex-символа и положите в EMULATION_SESSION_KEY
   # Linux/macOS:
   echo "EMULATION_SESSION_KEY=$(openssl rand -hex 32)" >> .env
   ```

2. (Только для Live) Извлечь cookies MEXC:
   ```bash
   # Залогиниться в MEXC Futures в Chrome, закрыть браузер
   cargo run --example extract_cookies
   ```

3. Запуск backend (терминал 1):
   ```bash
   cargo build --release
   cargo run --release
   ```
   В логе должно появиться:
   ```
   🚀 Starting HFT Arbitrage System
   ✅ Configuration loaded successfully
   ✅ Price feed manager initialized
   🌐 Starting WebSocket server on 0.0.0.0:3001
   📊 Starting price feeds...
   ```

4. Запуск frontend (терминал 2):
   ```bash
   cd frontend
   npm install
   npm start
   ```

5. Открыть в браузере: **http://localhost:4200**

### Проверка работоспособности
- `curl http://localhost:3001/health` → `OK`
- `curl http://localhost:3001/health/detailed` → JSON с состоянием Binance/MEXC
- На дашборде индикатор **LIVE** (зелёный), цены обновляются в реальном времени.

### Запуск в Docker
```bash
cp .env.example .env
docker-compose up -d
# backend:  http://localhost:3001
# frontend: http://localhost:4201
docker-compose logs -f
docker-compose down
```

### Остановка
`Ctrl+C` в терминале backend — система корректно завершит активные операции за ~2 секунды.

## 7. Что умеет дашборд

### Мониторинг реального времени
- Цены Binance Futures и MEXC Futures с отметкой «LIVE»/«STALE».
- Спред в % с визуализацией и подсветкой возможностей.
- Анализ лага: биржевой лаг MEXC, сетевой лаг нашего подключения, системная задержка.
- Алерт «ARBITRAGE OPPORTUNITY» при лаге > 2 с и разнице цен > $10.
- История цен (последние 50 снимков).

### Управление торговлей
- Кнопки **Запустить** / **Остановить** торговлю.
- Переключение режима **Эмуляция ↔ Live** (с обязательным подтверждением перед Live).
- Страница настроек стратегии с предустановками:
  - **Safe** — max 1 позиция, momentum 0.05%, quick exit 1.5 с, веса 40/50/10.
  - **Balanced** — max 2, momentum 0.03%, quick exit 2 с, веса 60/30/10.
  - **Aggressive** — max 3, momentum 0.02%, quick exit 3 с, веса 80/15/5.
- Настройки капитала: баланс, процент позиции, плечо (1–200x), максимум позиций (1–10).
- Кнопка **Apply Settings** отправляет параметры по WebSocket без перезапуска backend.

### Позиции и сделки
- Панель открытых позиций: сторона (Long/Short), размер, цена входа, текущая цена, текущий PnL, trailing stop.
- Таблица истории закрытых сделок с причиной закрытия (TakeProfit / StopLoss / Timeout).
- Статистика из БД: всего сделок, win rate, средний PnL, лучшая и худшая сделки, текущий баланс, доходность в процентах, статус ликвидации.

### Браузерная эмуляция (для Live)
- Страница Browser Control: запуск Chrome, статус, отправка тестовых ордеров.
- Страница Cookie Management: извлечение, обновление, удаление cookies MEXC.
- Статус эмуляции: активность браузера, сессии, jitter.

## 8. Ключевые параметры конфигурации (`config.toml`)

```toml
[exchanges]
binance_ws = "wss://fstream.binance.com/ws/btcusdt@aggTrade"
mexc_ws    = "wss://contract.mexc.com/edge"

[trading]
symbol               = "BTC/USDT"
initial_capital      = 100.0   # стартовый баланс $
position_size_percent = 10.0   # % от баланса на сделку
leverage             = 200.0   # плечо
max_positions        = 2       # одновременно открытых позиций
binance_fee          = 0.0004
mexc_fee             = 0.0002

[monitoring]
stale_timeout_ms            = 300
latency_warning_threshold_ms = 100

[api]
host = "0.0.0.0"
port = 3001                    # WebSocket + REST
cors_origins = ["http://localhost:4200"]

[emulation]
trading_mode     = "Hybrid"    # Hybrid | Aggressive
browser_profile  = "Chrome145Windows64"
```

Важно: `main.rs` использует `PositionManager` со стратегией `ImpulseStrategy`, режимы `DryRun/Paper/Live` из `src/trading/executor.rs` актуальны только для альтернативного `TradingEngine` в API `trading_control`. Основные режимы — **Emulation** и **Live** через `SystemManager`.

## 9. Какие функции выполняет система (кратко)

1. **Сбор рыночных данных** — одновременные WebSocket к Binance и MEXC с реконнектом и circuit breaker.
2. **Расчёт состояния** — `PriceState` с ценами, спредом, лагами и индикатором возможности.
3. **Стратегия** — взвешенная сумма импульса, статистики лага и разницы цен.
4. **Управление позициями** — открытие с учётом капитала и плеча, закрытие по TP/SL/таймауту, защита от дубликатов.
5. **Управление капиталом** — комиссии, накопленный объём, проверка на ликвидацию.
6. **Разделение режимов** — две независимые БД для Emulation и Live.
7. **Исполнение ордеров** — Binance через REST API, MEXC через браузер (CDP + cookies).
8. **WebSocket API** — рассылка состояния с дросселированием до 20 сообщений в секунду, приём команд.
9. **Мониторинг** — `/health`, гистограммы задержек в логах каждые 30 секунд, health checkers.
10. **Дашборд** — наглядное отображение, ручное управление, настройка стратегии в реальном времени.

---

## 10. Производительность

- Парсинг JSON: <100 μs (`simd-json` + fast-float).
- Расчёт спреда: <10 μs.
- Обработка сигнала: <1 мс.
- Throughput WebSocket: >1000 msg/s.
- Выполнение ордера: Binance ≈ 50 мс, MEXC через браузер ≈ 500 мс.
- WebSocket рассылка на клиент: throttling до 20 обновлений в секунду.

---

## 11. Что стоит помнить

- Live режим — это **реальные деньги** и реальный браузер. Всегда начинайте с Emulation.
- Файл `.env` не коммитить; `EMULATION_SESSION_KEY` должен быть уникальным.
- Для production лучше сменить `host = "0.0.0.0"` на `127.0.0.1` и добавить аутентификацию к WebSocket.
- История сессии хранится в `.kiro/emulation.db` и `.kiro/live.db` — их можно удалять для сброса.

---

**Итого**: Rust-бэкенд ловит задержку MEXC относительно Binance, открывает короткие арбитражные позиции через браузерную эмуляцию или REST, а Angular-дашборд даёт полный контроль и наблюдаемость в реальном времени.
