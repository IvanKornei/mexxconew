# Requirements Document

## Introduction

Данная спецификация описывает добавление функций управления системой арбитражной торговли, включая возможность запуска/остановки торговой стратегии и переключения между режимами эмуляции и live торговли. Система должна обеспечивать безопасное управление торговыми операциями и четкое разделение между тестовым и реальным режимами работы.

## Glossary

- **Trading System**: Система арбитражной торговли, включающая бэкенд на Rust и фронтенд на Angular
- **Position Manager**: Компонент бэкенда, управляющий открытием и закрытием торговых позиций
- **WebSocket Server**: Сервер на базе Axum, обеспечивающий двустороннюю связь между бэкендом и фронтендом
- **Emulation Mode**: Режим эмуляции, в котором сделки не отправляются на биржу, но логика торговли работает полностью
- **Live Mode**: Режим реальной торговли, в котором сделки отправляются на биржу через API
- **Control Panel**: Панель управления на фронтенде для управления системой
- **System State**: Состояние системы (running/stopped, emulation/live)

## Requirements

### Requirement 1

**User Story:** Как трейдер, я хочу иметь возможность запускать и останавливать торговую стратегию через UI, чтобы контролировать когда система может открывать новые позиции

#### Acceptance Criteria

1. WHEN пользователь нажимает кнопку "Start Trading", THE Trading System SHALL активировать Position Manager для обработки торговых сигналов
2. WHEN пользователь нажимает кнопку "Stop Trading", THE Trading System SHALL деактивировать Position Manager и прекратить открытие новых позиций
3. WHILE Trading System находится в состоянии "stopped", THE Position Manager SHALL игнорировать все торговые сигналы
4. WHEN Trading System останавливается, THE Trading System SHALL сохранить все открытые позиции без их принудительного закрытия
5. THE Control Panel SHALL отображать текущее состояние системы (running/stopped) с визуальной индикацией

### Requirement 2

**User Story:** Как трейдер, я хочу переключаться между режимами эмуляции и live торговли, чтобы тестировать стратегию без риска реальных потерь

#### Acceptance Criteria

1. THE Trading System SHALL поддерживать два режима работы: emulation и live
2. WHEN система находится в режиме emulation, THE Position Manager SHALL выполнять всю торговую логику без отправки реальных ордеров на биржу
3. WHEN система находится в режиме live, THE Position Manager SHALL отправлять реальные ордера на биржу через Exchange API
4. WHEN пользователь переключает режим, THE Trading System SHALL применить новый режим только после подтверждения пользователя
5. THE Control Panel SHALL отображать текущий режим работы с четкой визуальной индикацией (emulation/live)

### Requirement 3

**User Story:** Как трейдер, я хочу видеть отдельные вкладки для режимов эмуляции и live, чтобы четко разделять тестовые и реальные данные

#### Acceptance Criteria

1. THE Control Panel SHALL содержать две вкладки: "Emulation" и "Live Trading"
2. WHEN пользователь выбирает вкладку "Emulation", THE Trading System SHALL отображать данные и статистику только для режима эмуляции
3. WHEN пользователь выбирает вкладку "Live Trading", THE Trading System SHALL отображать данные и статистику только для режима live торговли
4. THE Trading System SHALL сохранять историю сделок и статистику отдельно для каждого режима
5. THE Control Panel SHALL визуально различать вкладки с использованием цветовой индикации (например, зеленый для эмуляции, красный для live)

### Requirement 4

**User Story:** Как трейдер, я хочу чтобы система предотвращала случайное переключение в live режим, чтобы избежать непреднамеренных реальных сделок

#### Acceptance Criteria

1. WHEN пользователь пытается переключиться из режима emulation в режим live, THE Trading System SHALL отобразить модальное окно подтверждения
2. THE Trading System SHALL требовать явного подтверждения перед активацией live режима
3. IF система находится в состоянии "running" И пользователь пытается переключить режим, THEN THE Trading System SHALL сначала остановить торговлю, затем запросить подтверждение
4. THE Control Panel SHALL отображать предупреждающее сообщение о рисках при переключении в live режим
5. WHEN пользователь подтверждает переключение в live режим, THE Trading System SHALL записать событие в лог с временной меткой

### Requirement 5

**User Story:** Как трейдер, я хочу чтобы система сохраняла состояние (running/stopped, режим) между перезапусками, чтобы не настраивать систему заново каждый раз

#### Acceptance Criteria

1. WHEN Trading System запускается, THE Trading System SHALL загрузить последнее сохраненное состояние из конфигурационного файла
2. THE Trading System SHALL сохранять текущее состояние (running/stopped, emulation/live) в файл при каждом изменении
3. IF конфигурационный файл не существует при первом запуске, THEN THE Trading System SHALL создать файл с безопасными значениями по умолчанию (stopped, emulation)
4. THE Trading System SHALL использовать формат JSON для хранения состояния системы
5. WHEN система восстанавливает состояние "running" в режиме live, THE Trading System SHALL запросить подтверждение пользователя перед активацией

### Requirement 6

**User Story:** Как разработчик, я хочу чтобы система корректно обрабатывала отрицательные значения лагов, чтобы понимать реальную синхронизацию данных между биржами

#### Acceptance Criteria

1. THE Trading System SHALL вычислять лаг как разницу между временными метками данных от бирж
2. WHEN данные от MEXC приходят раньше данных от Binance, THE Trading System SHALL отображать отрицательное значение лага
3. WHEN данные от MEXC приходят позже данных от Binance, THE Trading System SHALL отображать положительное значение лага
4. THE Trading System SHALL использовать абсолютное значение лага для определения торговых возможностей
5. THE Control Panel SHALL отображать как положительные, так и отрицательные значения лагов с соответствующей интерпретацией
